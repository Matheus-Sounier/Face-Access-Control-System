# Face Access Control System

## Overview

Real-time facial recognition access control system using MediaPipe for face detection, InsightFace for facial embeddings, and FastAPI + Streamlit in a modular architecture. Data is stored in an Oracle Database running in Docker.

The project includes two AI-powered analytics features:
- A natural-language chat that queries access logs via a text-to-SQL agent.
- Automatic visual descriptions of unrecognized faces, generated by a multimodal model.

## Installation

### Clone the repository

```bash
git clone git@github.com:Matheus-Sounier/Face-Access-Control-System.git
cd Face-Access-Control-System
```

---

### Configure environment variables

Copy the example file and provide your own values.

```bash
cp .env.example .env
```

---

### Oracle Database Setup

Access the Oracle container:

```bash
docker exec -it -u oracle oracle_face_detection sqlplus / as sysdba
```

Switch to the pluggable database:

```sql
ALTER SESSION SET CONTAINER = FREEPDB1;
```

Create the application user:

```sql
CREATE USER your_app_user IDENTIFIED BY your_password;
GRANT CONNECT, RESOURCE TO your_app_user;
GRANT UNLIMITED TABLESPACE TO your_app_user;
```

### Read-only user for the AI Analytics Chat

The `/analytics/chat` endpoint uses a dedicated Oracle user with read-only privileges. This user is isolated from the application's main database account to prevent any AI-generated SQL from modifying the database.

Grant the required permissions:

```sql
GRANT CREATE SESSION TO <analytics_user>;

GRANT SELECT ON your_app_user.DETECTED_PEOPLE TO <analytics_user>;
GRANT SELECT ON your_app_user.ACCESS_LOGS TO <analytics_user>;
```

Since the tables live in `your_app_user`'s schema, `<analytics_user>` needs synonyms to query them without schema-qualifying every statement (the SQL agent generates unqualified table names):

```sql
CREATE SYNONYM <analytics_user>.DETECTED_PEOPLE FOR your_app_user.DETECTED_PEOPLE;
CREATE SYNONYM <analytics_user>.ACCESS_LOGS FOR your_app_user.ACCESS_LOGS;
```

> **Note:** if you ever drop and recreate `DETECTED_PEOPLE` or `ACCESS_LOGS` (e.g. during a schema migration), the `GRANT` above becomes invalid — Oracle grants are tied to the underlying object, not the table name. You'll need to re-run the `GRANT SELECT` statements after any such change, even though the synonyms themselves keep working.

This user **must not** receive:

- INSERT
- UPDATE
- DELETE
- DROP

Its credentials should exist only inside the local `.env` file and should never be committed.

### Download the local face detection model

The desktop application performs face detection locally and therefore requires its own MediaPipe model.

```bash
mkdir -p models

curl -o models/blaze_face_full_range.tflite \
https://storage.googleapis.com/mediapipe-models/face_detector/blaze_face_full_range/float16/1/blaze_face_full_range.tflite
```

> The API downloads its own copy of this model during the Docker build. This download is only required for the desktop application.

---

### Run the API and Dashboard

From the project root:

```bash
docker compose up -d --build
```

This starts:

- `fastapi_app` (port **8000**)
- `streamlit` (port **8501**)
- `oracle`

If the API fails during startup:

```bash
docker compose logs -f fastapi_app
```

---

### Run the desktop application

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it.

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements-desktop.txt
```

Run the application:

```bash
python main.py
```

The desktop application opens your webcam, performs local face detection, and sends cropped faces to the API for recognition.

## Usage

### Enroll a person

```bash
curl -X POST http://localhost:8000/enroll \
  -F "name=elon" \
  -F "employee_id=0099" \
  -F "access_level=Employee" \
  -F "photo_1=@photo1.png" \
  -F "photo_2=@photo2.png" \
  -F "photo_3=@photo3.png"
```

Only `photo_1` is required.

Using multiple photos generally improves recognition accuracy.

---

### Recognize a face

```bash
curl -X POST http://localhost:8000/recognize \
  -F "file=@photo.png"
```

## Common Issues

### Oracle connection failed

Possible errors:

```text
ORA-12514
ORA-12154
ORA-01109: database not open
```

Verify:

- Database host
- Port
- Service name
- Username
- Password
- Whether the Oracle container has completely finished starting

---

### FastAPI returns Internal Server Error

Inspect the container logs:

```bash
docker compose logs -f fastapi_app
```

---

### Camera not detected

- Ensure no other application is using the webcam.
- On Windows, `CameraStream` enables `use_dshow=True` by default. If the camera fails to open, try disabling it.

---

### Face detection model not found

Possible error:

```text
FileNotFoundError: No such file or directory
```

Verify that the file

```text
models/blaze_face_full_range.tflite
```

exists and matches the Installation instructions.
